# Test Strategy — Proving the Refactor Changes Nothing

TDD anchor for the theming work. The goal: Classic theme must produce byte-identical output to the pre-theme codebase.

## Golden file approach

### What golden files capture

Render output from each widget given a known input state. Captured before the refactor, asserted after.

### Files to create

```
thermal/internal/widgets/testdata/
  sparkline_classic.golden       # RenderSparkline output for known data+thresholds
  severity_gradient.golden       # severityColor output for 0,10,20,...,100 with CPU thresholds
  thermal_levels.golden          # renderCatCell output for each category at each level
  overall_levels.golden          # headline overall cell at each threat level
  session_diamonds.golden        # renderSessionDiamonds output for each phase
  breathing_dots.golden          # BreatheDots.Render output at known phases
  rates_line.golden              # Rates.View output for a known snapshot
  alerts_line.golden             # Alerts.View output for known alert set
```

### How to generate

Before starting the refactor, add a test that captures current output:

```go
func TestCaptureGoldenFiles(t *testing.T) {
    if os.Getenv("UPDATE_GOLDEN") != "1" {
        t.Skip("set UPDATE_GOLDEN=1 to regenerate golden files")
    }
    // ... render each widget with known inputs, write to testdata/
}
```

Run once: `UPDATE_GOLDEN=1 go test ./internal/widgets/ -run CaptureGolden`

### How to assert

After the refactor, the same test (without UPDATE_GOLDEN) compares output:

```go
func TestClassicThemeMatchesGolden(t *testing.T) {
    theme := theme.Classic()
    // ... render each widget with same known inputs, using classic theme
    // ... compare byte-for-byte with golden files
}
```

## What we don't test

- **Visual quality** — can't unit test "does this look good." That's what the swatch renderer and screenshots are for.
- **Terminal compatibility** — truecolor rendering is terminal-dependent. Trust the escape codes.
- **Performance** — LUT generation is trivially fast. No benchmark needed.

## STUB: Test data for each palette

Each built-in theme needs its own expected outputs for the theme-switching integration test. These will be generated by the swatch renderer once the palettes are finalized. The golden file approach only needs Classic (proving backward compat); other themes are validated visually.

## Execution

1. **Before refactor:** Write golden capture tests, run with `UPDATE_GOLDEN=1`, commit golden files
2. **During refactor:** Run `go test ./...` after each file migration — goldens catch regressions
3. **After refactor:** Add theme-switching integration tests
4. **Per new theme:** Visual validation via swatch renderer + screenshot
